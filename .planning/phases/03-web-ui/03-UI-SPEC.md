# Phase 3 — UI Design Contract

> Visual and interaction contract for the Russian read-only Streamlit app (`src/wbmon/ui/`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Authority order: `03-CONTEXT.md` decisions (locked) > this contract > `FEATURES.md` suggestions. This file refines CONTEXT; where it adds a detail, it is marked **(refinement)**. Nothing here contradicts a CONTEXT decision.
>
> Stack facts verified against the installed `.venv` (Streamlit 1.66.0, Plotly 7.1.0, pandas 3.0.6): theme keys listed in `.streamlit/config.toml` below exist in `streamlit/config.py`; `st.columns(gap=...)` / `st.container(gap=...)` accept `"xxsmall"` (4px), `"xsmall"` (8px), `"small"` (16px), `"medium"` (32px), `"large"` (64px) or an integer px; `font` accepts `"sans-serif"` (CONTEXT's "sans serif" means this value); markdown supports `:green-badge[...]` colour badges.

| Property | Value |

## Spacing Scale

Streamlit lays out by `gap` tokens, not free margins. All values are multiples of 4.

| Token | Value | Streamlit expression | Usage |
|-------|-------|----------------------|-------|
| xs | 4px | `gap="xxsmall"` | Inline badge / caption stacks, heartbeat line under freshness badge |
| sm | 8px | `gap="xsmall"` | Controls inside one group (segmented control + number input), sidebar totals lines |
| md | 16px | `gap="small"` (Streamlit default) | Default between widgets, between metric columns, between caption and chart |
| lg | 24px | `gap=24` (integer px) | Between header block and tabs; between a chart and the table below it |
| xl | 32px | `gap="medium"` | Between major blocks inside a tab (chart / characteristics / history) |
| 2xl | 48px | — | Not used in this phase (listed only to keep the scale complete) |
| 3xl | 64px | `gap="large"` | Not used in this phase |

Exceptions (all intentional, each with its reason):
- Heatmap cell height is 20px (a multiple of 4) — reason: the 14px in-cell glyph and 14px Y tick label need a 20px row to stay legible without overlap; Plotly margins are multiples of 4 so the figure stays on the 4px grid (see Heatmap).
- Fixed component heights, all multiples of 4 — reason: Streamlit tables and Plotly figures need an explicit pixel height to keep the layout stable between reruns:
  - chart 520px: tall enough to separate up to 15 series and a bottom legend without scrolling;
  - history table 400px and run-log table 420px: roughly 10 visible rows, so the next block stays reachable;
  - SERP table 640px: about 16 rows visible, the rest scrolls inside the table (200 rows would otherwise push the page);
  - heatmap scroll container 480px: shows about 20 of 70 query rows and scrolls the rest, so the run table below remains reachable.
- Streamlit's own internal widget padding is not overridden.
- Main-area width: `layout="wide"`; sidebar at Streamlit default width. Supported viewport: >= 1024px wide desktop. Narrower screens degrade by Streamlit's automatic column stacking; no mobile-specific layout is specified.

## Typography

Exactly 4 sizes and 2 weights. Streamlit renders the base at `baseFontSize = 16`.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Caption / small | 14px | 400 | 1.5 | `st.caption`, sidebar totals, table cell text in `st.dataframe`, chart axis labels/legend/hover (Plotly `font.size = 14`), heatmap tick labels and in-cell glyphs, heartbeat line, badges |
| Body | 16px | 400 | 1.5 | `st.markdown` body text, widget labels, «О сервисе» prose, banners (`st.info/warning/error`) |
| Heading (h2/h3, `st.subheader`) | 20px | 600 | 1.2 | Block headings inside tabs («Характеристики», «Журнал сборов»), `st.metric` value (`metricValueFontSize = "20px"`) |
| Display (h1, `st.title`) | 28px | 600 | 1.2 | Page title only |

Weights: **400** (regular) and **600** (semibold) only. `baseFontWeight = 400`; `headingFontWeights = [600, 600, 600]`; `metricValueFontWeight = 600`. Bold in markdown (`**x**`) renders at Streamlit's default semibold and is the only emphasis; no italics for meaning.

Streamlit heading config: `headingFontSizes = ["28px", "20px", "20px"]` (h1, h2, h3; h4–h6 unused). Sidebar headings are not used (sidebar uses captions and widget labels only).

No exceptions: heatmap X/Y tick labels and in-cell status glyphs also use the 14px Caption size. Nothing may deviate from the 4 sizes above.

Numbers: tabular numerals are not available in the theme; align numeric columns right (Streamlit default for `NumberColumn`).

## Color

Light theme only (dark theme is out of scope, per CONTEXT Area 1 #3).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`backgroundColor`) | Page background, chart paper/plot background, table body |
| Secondary (30%) | `#F4F5F7` (`secondaryBackgroundColor`) | Sidebar, dataframe header, expander and bordered-container backgrounds, input backgrounds |
| Accent (10%) | `#7B2CBF` (`primaryColor`) | See reserved list below |
| Text | `#1A1D21` (`textColor`) | All text (16.7:1 on white); Streamlit derives secondary text (captions) at ~60% mix, expected to land at about 4.5:1 — verify visually, do not lighten `textColor` |
| Destructive | none | The app is read-only; there are no destructive actions. Red is used only for the status semantics below |

Accent (`#7B2CBF`, contrast 7.1:1 on white) reserved for:
1. The active segment of the period control and the selected tab underline.
2. Selected-value chips in the product multiselect and the select-slider thumb/track.
3. The «Скачать CSV» button (the only primary button) and keyboard focus rings.
4. Text links (`linkColor = "#6A1FA8"`, darker tint of the accent for contrast) — WB ID links in tables, repository link.

Accent is NOT used for: chart series colours, status colours, banners, table content, page title, or decorative fills.

### Status semantics (single source of truth, used by badges, banners, run log and heatmap)

Status is never conveyed by colour alone: every status carries an emoji AND a Russian word; the heatmap additionally carries a glyph inside each cell.

| Key (DB value) | Emoji + label (Russian) | Applies to | Heatmap fill | Heatmap glyph (colour) | Badge colour |
|----------------|-------------------------|------------|--------------|------------------------|--------------|
| `ok` | ✅ Успешно | run, query | `#2B8A3E` | `✓` (white) | green |
| `partial` | 🟡 Частично | run, query | `#F2C037` | `~` (`#1A1D21`) | yellow |
| `blocked` | ⛔ Заблокировано | run, query | `#C92A2A` | `✕` (white) | red |
| `rate_limited` | 🚦 Лимит запросов | query only | `#D9480F` | `!` (white) | orange |
| `error` | ❌ Ошибка | run, query | `#6C757D` | `E` (white) | gray |
| `abandoned` | ⏸ Прерван | run only | not in heatmap (see rule) | — | gray |
| `running` | ⏳ Идёт | run only | not in heatmap (see rule) | — | blue |
| (no row) | пусто | heatmap only | `#FFFFFF` | none | — |

Rules: `abandoned`/`running` runs appear in the run table but are excluded from the heatmap columns (no per-query rows to show). A run with `n_queries` smaller than 70 (limited runs) shows missing cells as white/empty.

Theme colour keys aligned with the table above: `greenColor="#2B8A3E"`, `redColor="#C92A2A"`, `orangeColor="#D9480F"`, `yellowColor="#F2C037"`, `yellowTextColor="#7A5B00"`, `grayColor="#6C757D"`.

### Chart colours

- **Series palette (15, qualitative, each >= 3:1 against white for line strokes).** Applied in order by position in the current selection, defined once as `SERIES_COLORS` in `charts.py` and mirrored in `theme.chartCategoricalColors`:

  | # | Hex | # | Hex | # | Hex |
  |---|-----|---|-----|---|-----|
  | 1 | `#1F77B4` | 6 | `#8C564B` | 11 | `#B26A00` |
  | 2 | `#E8590C` | 7 | `#D6336C` | 12 | `#495057` |
  | 3 | `#2B8A3E` | 8 | `#0C8599` | 13 | `#A61E4D` |
  | 4 | `#7048E8` | 9 | `#5C940D` | 14 | `#087F5B` |
  | 5 | `#C92A2A` | 10 | `#364FC7` | 15 | `#862E9C` |

- **Redundant encoding for 15 series** (colour alone cannot separate 15 hues): series 1–8 use solid lines, series 9–15 use `line.dash="dash"`; every series is named `ID {nm_id} · {brand|—}` in the legend; hover is `hovermode="closest"` and shows the series name; legend click toggles a series, double-click isolates it.
- Failed-run band fill: `rgba(134,142,150,0.20)` (neutral grey, `layer="below"`, no outline). Legend entry text «сбор не удался» (not colour-only: it has a label).
- Grid lines `#E9ECEF`; axis lines `#CED4DA`; plot and paper background `#FFFFFF`.
- Ad marker: diamond shape (shape, not colour, is the signal); same colour as its series.

## Layout & Information Architecture

Single page, `st.set_page_config(page_title="WB SERP Monitor — позиции в поиске Wildberries", page_icon="📈", layout="wide")`. No multipage navigation.

```
┌ Sidebar (secondary bg) ┐ ┌ Main ─────────────────────────────────────────────────┐
│ Фильтры                │ │ H1 Мониторинг позиций в поиске Wildberries            │
│  Поисковый запрос      │ │ caption: 70 запросов · топ-200 · Москва · сбор каждый │
│  [selectbox]           │ │          час                                          │
│  Период [segmented]    │ │ [freshness badge]         caption: Сборщик: …         │
│  Товаров по умолчанию  │ │ [status banner — only when applicable]                │
│  [number_input 5]      │ │ ─ tabs ───────────────────────────────────────────────│

└────────────────────────┘ └───────────────────────────────────────────────────────┘
```

### Visual hierarchy and reading order

Page reading order: **freshness badge → status banner (if any) → tab content**, so the user first learns how fresh and how trustworthy the data is, then sees the chart.

Primary visual anchor per tab (the element that must dominate the tab by size and position; everything else is supporting):

| Tab | Primary anchor | Supporting elements |
|-----|----------------|---------------------|
| 📈 Позиции | Position chart (520px, directly under the product picker) | picker, caption, summary line, characteristics table, history expander, CSV button |
| 🗂 Выдача | Snapshot table (640px, full top-N) | slider, four metrics above it |
| 🩺 Журнал сборов | Status heatmap (query × run) | summary badges, legend row, run table below |
| ℹ️ О сервисе | Text (Body 16px prose with 20px subheadings) | none |

Header zone order (top to bottom, md/16px gaps, lg/24px before tabs):
1. `st.title("Мониторинг позиций в поиске Wildberries")` — Display 28/600.
2. `st.caption("70 запросов · топ-200 · Москва · сбор каждый час")`.
3. Freshness row: `st.columns([3, 2], gap="small")` — left: freshness badge (markdown colour badge, Body 16); right: collector heartbeat as `st.caption` (14px). On narrow widths they stack.
4. Banner (`st.warning`/`st.error`/`st.info`) only when the Status Banner rules below fire — directly under the freshness row, above tabs, so it is visible on every tab.

Tab labels (exact): `📈 Позиции`, `🗂 Выдача`, `🩺 Журнал сборов`, `ℹ️ О сервисе`. Default tab is «Позиции».

Sidebar (exact order and labels):
1. `st.header`-less group title via `st.markdown("**Фильтры**")`.
2. `st.selectbox("Поисковый запрос", ...)`, options in sheet order, label `"{sheet_order:02d}. {text}"` (original wording, no case/space changes), default = first query. Type-to-filter is Streamlit's built-in.
3. `st.segmented_control("Период", ["24 ч", "7 дней", "Всё время"], default="Всё время")`. Streamlit allows deselecting a segment (returns `None`): `None` MUST be treated as «Всё время» **(refinement)**.
4. `st.number_input("Товаров по умолчанию", min_value=1, max_value=20, value=5, step=1, help="Сколько товаров из текущего топа выбирается автоматически")`.
5. `st.divider()` then totals block (below).

Sidebar totals block — five caption lines (14px, label regular, value `**semibold**`, numbers with thin-space thousands separator), 8px (sm) between lines, inside `st.container(border=True)`:
- `Всего сборов: **{N}**`
- `Успешных сборов: **{N}**`
- `Первый сбор: **{DD.MM.YYYY HH:MM}** МСК` (or `—`)
- `Наблюдений в базе: **{N}**`
- `Уникальных товаров: **{N}**`

No `st.metric` in the sidebar (keeps the typography within 4 sizes). «Успешных» means runs with status `ok` or `partial` that stored >= 1 observation **(refinement; planner must keep one definition, same as the freshness badge's "successful run")**.

| Heartbeat line | `st.caption` | `Сборщик: на связи, сигнал {age} назад` when file age <= `HEARTBEAT_STALE_S`; `Сборщик: нет сигнала уже {age}` when older; `Сборщик: нет данных (файл сигнала не найден)` when `scheduler_heartbeat.json` is absent (not an error, no red styling). `HEARTBEAT_STALE_S` is a named constant in `ui/data.py`, default 600 s; **Phase 2 must tell Phase 3 its heartbeat write interval; the constant must be >= 2x that interval**. ### Status banner rules (evaluated on the latest run row, newest `runs.id`)

| Situation | Element | Copy |
|-----------|---------|------|
| No DB file | `st.info` + `st.stop()` after header | `База данных ещё не создана. Запустите `wbmon init-db`, затем `wbmon collect`.` |
| DB exists, zero runs | `st.info` | `Сборов ещё не было. Первый сбор — в ближайшие :00 по МСК.` |
| Latest run `running` | `st.info` | `⏳ Идёт сбор (начат {HH:MM} МСК). Данные появятся после завершения.` |
| Latest run `ok` | none | — |
| Latest run `partial` | `st.warning` | `🟡 Последний сбор завершён частично: успешно {ok} из {n} запросов, заблокировано {blocked}, с ошибкой {error}. Пропуски на графике за этот сбор помечены серой полосой. Следующая попытка в {HH}:00 МСК.` |
| Latest run `blocked`, earlier successes exist | `st.warning` | `⛔ Последний сбор заблокирован Wildberries (HTTP {code}) по {blocked} из {n} запросов. Данные за этот час не подставляются. Следующая попытка в {HH}:00 МСК.` (HTTP code = most frequent `http_status` among blocked attempts; omit «(HTTP …)» if unknown) |
| **No successful run ever** and latest run `blocked` (all runs blocked) | `st.warning` | `⛔ Wildberries отклоняет запросы сборщика (антибот, HTTP 403). Запуски продолжаются каждый час и фиксируются в «Журнале сборов»; данные не подставляются.` (locked CONTEXT copy; HTTP code substituted if the observed code differs from 403) |
| Latest run `error` | `st.error` | `❌ Последний сбор завершился ошибкой. Подробности — на вкладке «Журнал сборов». Следующая попытка в {HH}:00 МСК.` |
| Latest run `abandoned` | `st.warning` | `⏸ Последний сбор был прерван (перезапуск или остановка сборщика). Следующая попытка в {HH}:00 МСК.` |

"Next attempt" = next full hour in `Europe/Moscow` after now. Only one banner is shown at a time (first matching row wins).

### Tab «📈 Позиции»

Vertical order, xl/32px between blocks:

1. **Product picker** — `st.multiselect("Товары (ID, бренд или название)", options=<nm_id ints>, format_func=<label>, default=<top-N>, max_selections=15, key=f"products_{query_id}_{top_n}")`.
   - Options are `nm_id` integers; the label comes from `format_func` so that labels can change between runs without invalidating a stored selection **(refinement)**.
   - Label: `"{nm_id} · {brand or '—'} · {name[:40]}"`; add suffix ` · не в последней выдаче` for products absent from the latest successful run of this query (FEATURES copy).
   - Option order: current position asc (latest successful run), then best position asc; products not in the latest run last.
   - Default = first `min(top_n, 15)` products of the latest successful run for this query. Key contains query id AND sidebar N, so changing either resets the selection. If sidebar N > 15, show `st.caption("Показано не более 15 товаров — ограничение для читаемости графика.")` below the picker.
   - If the user selects nothing: `st.info("Выберите хотя бы один товар, чтобы увидеть график.")`; the chart still renders as an empty skeleton (axes + failed-run bands).
   - Note: Streamlit's own built-in strings (multiselect "no results" and max-selection hint, dataframe toolbar tooltips, download tooltip) are English and cannot be localised in 1.66; this is a known, accepted limitation, not a defect.
2. **Chart** — see Chart contract.
3. **Chart caption** — `st.caption`, exact text: `Позиция 1 — сверху. Разрыв линии — товара не было в топ-{top_n} в этом сборе; значения не достраиваются. Серая полоса — сбор по запросу не удался, данных за этот час нет. ◆ — рекламное размещение.` (`top_n` = the run's actual `top_n`).
4. **Chart summary line (accessible text equivalent)** — `st.caption`: `Показано товаров: {k}; сборов в периоде: {n}; без данных (сбор не удался): {u}.`
5. **Characteristics table** under `st.subheader("Характеристики")` — see Tables.
6. **History expander** `st.expander("История наблюдений")` collapsed by default — see Tables.
7. **CSV button** — `st.download_button("Скачать CSV", ..., mime="text/csv", type="primary", icon=":material/download:")`, placed directly under the characteristics table, left-aligned, with `st.caption` to its right-hand context: `CSV: разделитель «;», десятичная запятая, кодировка UTF-8 с BOM — открывается в Excel.`

### Tab «🗂 Выдача»

1. `st.subheader("Выдача по запросу")` and `st.caption` with the selected query's label.
2. `st.select_slider("Момент сбора (МСК)", options=<runs with observations for this query>, value=<latest>, format_func=lambda: "DD.MM HH:MM")`. Only runs that have stored observations for the query.

**Recent attempts table (refinement; shared component `render_query_attempts(query_id, limit=10)`)** — also shown in «Позиции» when the selected query has zero observations. Columns: «Время (МСК)», «Статус» (emoji + label), «HTTP», «Страниц», «Товаров», «Причина» (`error_class`, `—` if NULL), «Длительность». Newest first, `hide_index=True`, auto height.

### Tab «🩺 Журнал сборов»

Columns: «Начало (МСК)» `DD.MM.YYYY HH:MM`, «Длительность» (`4 мин 12 с`; `идёт` for running; `—` if unknown), «Тип» («По расписанию» / «Вручную»), «Статус» (emoji + label), «Успешных», «Частичных», «Заблок.», «Ошибок» (query counts; `st.caption` above explains `Количество запросов по статусам; всего запросов в сборе — N`), «Товаров сохранено».

## Chart contract («Позиции»)

Plotly `go.Figure`, rendered with `st.plotly_chart(fig, width="stretch", config={"displaylogo": False, "modeBarButtonsToRemove": ["select2d", "lasso2d", "autoScale2d"]})`.

| Property | Value |
|----------|-------|
| Height | 520 (fixed) |
| Margins (px) | `l=64, r=16, t=16, b=88` |
| Series | One `go.Scatter` per selected product, `mode="lines+markers"`, `connectgaps=False`, `line.width=2`, `marker.size=7` (circle) / `10` (diamond for ads) |
| Series name | `ID {nm_id} · {brand or '—'}` (legend and hover header) |
| X | Moscow wall-clock, tz-naive datetimes (UTC→`Europe/Moscow`→drop tz) over the **full grid of all runs of the selected query inside the period** (not only runs where the product was found) |

### «ℹ️ О сервисе» copy (exact structure; text may be tightened but not extended, no new claims)

`st.subheader("О сервисе")`

> Сервис раз в час собирает выдачу Wildberries по 70 поисковым запросам и хранит историю позиций товаров. Данные не изменяются и не удаляются: каждая запись — реальное наблюдение.

`st.subheader("Что собирается")`
- Запросы: 70 формулировок из Google-таблицы «Запросы WB» (при её недоступности используется встроенная копия); текст запроса передаётся в Wildberries без изменений.
- Глубина: топ-200 по сортировке «по популярности», регион — Москва.
- Расписание: каждый час в :00 по московскому времени (МСК); время в базе хранится в UTC, на экране — МСК.

`st.subheader("Как читать данные")`
- Позиция — место в выдаче, считая рекламные места; 1 — первое.
- Цена — цена для покупателя без авторизации, минимальная по размерам товара.
- Рейтинг и отзывы — по карточке товара в выдаче.
- Срок доставки — календарные дни от момента сбора (0 — сегодня, 1 — завтра) по данным Wildberries (time1 + time2); оценка приблизительная.
- ◆ на графике — рекламное размещение.

`st.subheader("Честность данных")`
- Разрыв линии на графике — товара не было в топе при полном сборе. Значения не достраиваются.
- Серая полоса — сбор по запросу не удался (блокировка, ошибка, неполный ответ): о товарах за этот час ничего не известно.
- Если поле не получено от Wildberries, оно остаётся пустым, а не заменяется нулём.

`st.subheader("Ограничения")`
- Wildberries может блокировать автоматические запросы (антибот). Сервис не обходит защиту; заблокированные сборы фиксируются как таковые и видны в «Журнале сборов».
- Автоматизированный сбор может не соответствовать правилам площадки; сервис создан как тестовое задание.
- Страница не обновляется сама: новые данные появляются после перезагрузки или любого действия на странице.

`st.subheader("Исходный код")` → `[github.com/U-Steph/wb-serp-monitor](https://github.com/U-Steph/wb-serp-monitor)` (placeholder URL from CONTEXT; Phase 4 confirms the real one).

## Interaction Contract

| Interaction | Behaviour |
|-------------|-----------|
| Change query | Product picker resets to the new query's current top-N (key includes query id); Выдача slider resets to latest run with observations; chart/tables recompute |
| Change N | Picker resets to top-N of the same query (key includes N) |
| Change period | Re-filters chart, tables, CSV; picker options remain "ever seen for the query" (not narrowed by period) |
| Legend click / double-click | Plotly default (toggle / isolate); no app state |
| Hover | Per chart contract; no click handlers, no `on_select` |
| Table sort / column resize | Streamlit built-in only |
| Links | WB product links open in a new tab (LinkColumn default) |
| Refresh | No refresh button, no auto-rerun timer. Caches: loaders `@st.cache_data(ttl=60)` keyed on `(db_path, latest_run_id)`; the `latest_run_id` probe itself is uncached or `ttl <= 15` and uses a short-lived read-only connection |
| Keyboard | All controls are native Streamlit widgets (tab order, focus ring in accent). Charts are supplemented by the text summary line and tables, so no information is chart-only |

- Series: 15-colour palette + dash for 9–15 + named legend + closest-hover.
- Body text contrast >= 4.5:1; accent 7.1:1 on white; chart strokes >= 3:1.

```bash
docker compose up -d --build
```

## Сложности и решения

- **Антибот Wildberries.** С машины разработчика поисковый API отвечает 403 (`server: wbaas`), главная
  страница — 498. Обходить защиту я не стал (нет имитации браузера и TLS, токенов, прокси-ротации):
  такой сбор записывается как `blocked`, после трёх блокировок подряд предохранитель прекращает
  запросы, интерфейс честно показывает блокировки. Синтетических данных в базе нет. Автоматический сбор
  может противоречить правилам площадки; для промышленного использования нужен официальный канал.
- **Доступ к данным.** Что пробовал, ограничения и варианты решения — https://github.com/U-Steph/wb-serp-monitor/blob/main/docs/DATA_ACCESS.md; чтобы интерфейс можно было оценить без данных, в нём есть демо-режим на отдельной синтетической базе с пометкой «ДЕМО».
- **Формулировки запросов байт в байт.** `ё`, опечатка «2-спальный», кириллическая «х» против латинской
  «x» — текст идёт в Wildberries без `strip` и нормализации; встроенная копия 70 запросов страхует от
  недоступной Google-таблицы.
- **Честные разрывы.** Товар, которого нет в полном топе, даёт разрыв линии; сбор, который не удался, —
  серую полосу. Значения не достраиваются, неизвестные поля остаются `NULL`.
- **SQLite в режиме WAL для двух процессов.** Коллектор — единственный писатель (одна транзакция на
  запрос, триггеры запрещают `UPDATE` и `DELETE`), интерфейс открывает базу только на чтение.
- **Работа без присмотра.** Планировщик запускает новый процесс сбора каждый час, а файл-блокировка и
  уникальный слот часа исключают наложения; он пишет сигнал живости и корректно останавливается по
  SIGTERM. Прошлые часы не «добираются».
